- [x] **Response schemas for the analytic reports.** `future_timeline`, `income_per_location`, `investment_performance`, `monthly_pnl`, `nw_summary`, `recurrent_history` and `spending_analysis` have output schemas (`routes/schemas.py`, "Analytic reports"), with `Dict` / `List(Raw)` fields where the payload uses currency-named keys or list rows; `test/report_schemas_test.py` dumps real view output through each. `assets_by_location` and `valuation_history` (arrays of arrays) and `cash_flow` (rows keyed by `<currency>-<country>`) can't round-trip through marshmallow, so they're documented with OpenAPI objects via `@doc(responses=...)` and returned as is. `UNDOCUMENTED_RESPONSES` is gone from `test/schemas_test.py`.
- [x] **`_sort` / `_order` on list endpoints.** `sort_items()` (`lib/util.py`, next to `paginate()`) sorts in Python on the API field names, before slicing. `_sort` must be a field of the endpoint's output schema (400 otherwise); `_order` is ASC/DESC in any case; missing or `None` values go last in both directions; numbers sort before strings so mixed types don't raise, and strings compare case-insensitively. Each endpoint keeps its old order as the default when `_sort` is absent. Covers accounts, assets, instruments, payables, properties, bonds, CDs, both schedule lists, recurrents, recurrent transactions, monthly transactions, exchange rates and upcoming payments. Frontend lists whose order used to come from a backend remap of `id` now ask for it explicitly. Left as is: `dashboardBudgets` (config order) and `transactionParsers`; the list-shaped reports return chart rows the dashboards fetch directly, not react-admin records.

## Known bugs

### High

- [x] **`recurrent.identifier` and `account.id` are global primary keys.** Both tables now have an integer primary key `internal_id` (exposed read-only as `internalId`), and the name is unique per user: indexes `account_user_name (user_id, id)` and `recurrent_user_identifier (user_id, identifier)`. The API `id` is still the name. `account.institution` is renamed `location` (API field too), matching instruments.
  - Instruments have a required `account` (the account at the location, e.g. a brokerage account number), and their identifier is `Location_Account_Symbol` (`instrument_identifier()` in `models/instrument.py`; the model's `identifier` property, also in the API output). The unique index is `instrument_user_location_account_symbol`. Coinbase positions load as `Coinbase_Portfolio_<symbol>`.
  - `python -m scripts.migrate_internal_ids --base <dir>` (`--check` for a dry run) rebuilds the three tables, splits locations like `Citi_B5894` into location `Citi` + account `B5894`, gives instruments without one the account `TEMP`, rewrites every reference to a renamed instrument (and `Coinbase_<symbol>` references), and adds any missing per-user unique index. It replaces `scripts.add_unique_identifiers`, refuses to run while the result would hold duplicates, and saves a `.bak` copy first. Applied to the local `mflow-data/mydatabase.db` on 2026-11-17 (backup `mydatabase.db.20261117-120949.bak`); **still to run on the server** (it also covers the earlier unique indexes). `sample-base-dir/sqlite-db-schema.sql` is regenerated to match.
  - **To do by hand:** replace the `TEMP` accounts (e.g. `Citi_TEMP_VOO` → the real account like `B5894`). Editing the instrument's account in the UI moves every reference with it.

### Medium

- [x] **Hardcoded `USDPYG`** in `list_income` (`views/list_assets.py:50`); use the user's `SECONDARY_CURRENCY`.
- [x] **Changes can leave dangling targets or orphans.** Deletes now return 409 while other assets target the asset or recurrents are attached to it, while a bond/CD has schedule rows, or while a recurrent has transactions. Renames (instrument location/symbol, property name, payable description, bond/CD name) and an account currency change are refused (400) while used. Schedule POSTs and a recurrent's `assetId` must belong to the caller. `DELETE /bondSchedules/<id>` and `DELETE /depositCertificateSchedules/<id>` added so a bond/CD can be emptied before deleting it.
- [x] **Asset identifiers aren't unique, and several places assume they are.** Identifiers are now unique per user across every asset type. Creates and renames (accounts, instruments, payables, properties, bonds, CDs, recurrents) are refused with a 409 when another of the user's assets already has the identifier (`duplicate_error` in `lib/util.py`). Unique indexes back this up per table: `instrument (user_id, location, symbol)`, `payable (user_id, description)`, `property (user_id, property_name)`, `bond (user_id, name)`, `deposit_certificate (user_id, name)`; any `IntegrityError` becomes a 409. Uniqueness across types is enforced by the routes only. The code that assumed unique identifiers (Future Timeline `targets` / `sale_dates`, `validate_pool_target`, `target_country`, `GET /assets/<id>`, row ids in Upcoming Payments and Monthly Transactions, frontend selectors and keys) is left as is, since duplicates can no longer be created.
  - Existing databases get these indexes from `python -m scripts.migrate_internal_ids` (which replaced `scripts.add_unique_identifiers`).
- [x] **Monthly P&L summary only totals USD and the secondary currency.** Amounts in any other currency (e.g. USDC) are converted to USD at the current rate (`totals_currency()` in `reports/pnl.py`), so they count in the monthly USD sums and the totals. A currency without a USD rate is logged and left out, as before.
- [x] **A referenced asset couldn't be renamed, so `TEMP` instrument accounts couldn't be fixed on target pools.** Renaming an instrument (location or account), payable, property, bond or CD now moves the user's references along with it (`rename_references()` in `lib/util.py`: every `target_asset_id`, recurrent `parent_asset_id` and transaction `paid_with`), including a pool that compounds into itself. Another user's rows are untouched. A new name that another of the user's assets has is still a 409. An instrument's symbol still can't change while it's a target (400), since targets must hold the source's currency. The instrument edit form now allows changing the location too.
- [ ] **Frontend hardcodes PYG as the secondary currency.** `dashboards/MonthlyPNL.tsx` (`income_PYG` / `expenses_PYG` columns and `USDPYG`), `dashboards/CashFlow.tsx` (`PYG-PY` column), `dashboards/IncomePerLocation.tsx` (header) and `recurrentTransaction.tsx` (totals and `USDPYG`). A user with another `SECONDARY_CURRENCY` gets blank or wrong columns; read it from the payloads (`summary.secondary_currency`, `secondary_currency`) or the profile.
